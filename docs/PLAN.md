# CCTV AI 에이전트 — 구상서

> 목표 일정: **2026-10-28 (화) 1차 완성 / 시연**
> 한 줄 정의: 현장의 CCTV 화면을 한곳에서 보면서, AI가 **위험 요소를 찾아 알려주고**, 사람이 쓰러지거나 크게 다치면 **상황을 판단해 112/119 신고까지 이어주는** 보조 관제 에이전트.

---

## 1. 핵심 기능

### 1-1. 관제 화면 (UI)
| 기능 | 설명 |
|---|---|
| 분할 화면 직접 설정 | 1 / 4 / 9 / 16 분할 프리셋 + **가로×세로 직접 입력**(예: 3×2, 5×4). 설정은 브라우저에 저장 |
| 클릭 시 확대 | 카메라 타일 클릭 → 전체화면 확대 뷰 |
| 좌우 넘김 | 확대 뷰에서 ◀ ▶ 버튼, 키보드 ←/→, 모바일 스와이프로 이전/다음 카메라 |
| 페이지 넘김 | 카메라 수가 분할 수보다 많으면 그리드도 페이지 단위로 좌우 넘김 |
| 위험 표시 | AI가 감지한 객체에 박스/라벨, 위험도별 테두리 색(주의=노랑, 위험=주황, 긴급=빨강 점멸) |
| 이벤트 패널 | 우측에 시간순 이벤트 목록, 클릭 시 해당 카메라 확대 |
| 긴급 모달 | 긴급 상황 발생 시 화면 전체 경보 + 신고 카운트다운 (취소 / 즉시 신고) |

### 1-2. AI 인식 항목 (현장 주의 요소)
| 우선순위 | 항목 | 판단 근거 | 위험도 | 조치 |
|---|---|---|---|---|
| ★ 1차 | **쓰러짐(낙상)** | 사람 박스 비율 급변(세로→가로) + 무게중심 급하강, 포즈 키포인트 몸통 각도 | 위험 | 관리자 알림 |
| ★ 1차 | **쓰러진 뒤 움직임 없음** | 쓰러짐 이후 N초(기본 10초) 동안 움직임 거의 없음 → 의식불명/중상 의심 | **긴급** | **119 자동 신고 절차** |
| ★ 1차 | **화재 / 연기** | 화재·연기 객체 탐지가 연속 프레임에서 유지 | **긴급** | **119 자동 신고 절차** |
| ★ 1차 | 위험구역 진입 | 사용자가 그린 다각형 구역 안에 사람 발 위치 진입 | 주의~위험 | 알림 |
| ★ 1차 | 안전모 미착용 | 사람 + 안전모 탐지, 머리 영역에 안전모 없음 | 주의 | 알림 |
| 2차 | 폭행·싸움 | 근접한 2인 이상의 빠르고 큰 동작(포즈 속도) | **긴급** | **112 자동 신고 절차** |
| 2차 | 쓰러진 사람 주변 군집 | 쓰러짐 + 주변 인원 급증 | 위험 | 알림 |
| 2차 | 중장비 근접 | 사람–차량/지게차 거리 임계값 이하 | 위험 | 알림 |
| 2차 | 배회·장시간 체류 | 같은 트랙 ID가 구역 내 N분 이상 | 주의 | 알림 |

### 1-3. 상황 판단 → 신고 (가장 중요한 부분)
단일 프레임 결과로 바로 신고하면 오탐(앉기, 눕기, 물건 줍기)이 많기 때문에 **시간에 걸친 상태 머신**으로 판단합니다.

```
 사람 추적(track_id)
   │
   ▼
[정상] ──(비율 급변 + 급하강 / 몸통 각도 > 60°)──▶ [쓰러짐 의심]
   ▲                                                   │ 1.5초 이상 유지
   │ 다시 일어섬                                        ▼
   └──────────────────────────────────────────── [쓰러짐 확정] ── 알림(위험)
                                                       │ 10초간 움직임 < 임계값
                                                       ▼
                                               [무반응·중상 의심] ── 긴급 → 119 절차
```

**신고 에스컬레이션 정책 (Human-in-the-loop + 자동 발송)**
1. 긴급 이벤트 발생 → 관제 화면 전체 경보 + 담당자 휴대폰 푸시/문자
2. **카운트다운(기본 15초)** 동안 관리자가 `오탐 취소` 또는 `즉시 신고` 선택 가능
3. 아무도 응답 없으면 **자동 신고** 발송
   - 119: 화재/연기, 쓰러짐 후 무반응, 중상 의심
   - 112: 폭행/싸움, 침입 + 위협 행동
4. 신고 내용: 현장 주소, 카메라 위치명, 이벤트 종류, 발생 시각, 스냅샷 링크
5. 모든 판단·취소·신고 이력은 로그(DB)에 저장 → 사후 검증 및 임계값 튜닝

> ⚠️ **실제 112/119 연동 관련 주의**
> - 기계가 112/119로 직접 음성 자동전화를 거는 것은 허위·오신고 문제 때문에 사전 협의 없이 운영하면 안 됩니다.
> - 현실적인 1차 구현은 **(a) 현장 관리자/안전관리자에게 즉시 전화·문자**, **(b) 119·112 문자신고(번호 119 / 112로 SMS) 형식의 메시지 발송**, **(c) 계약된 보안·관제업체 연동** 순서로 구성하고, 실제 기관 직접 연동은 관할 소방서/경찰서 협의 후 활성화하는 구조로 만듭니다.
> - 그래서 코드상 신고 채널은 `mock`(시연용) / `sms` / `webhook` 어댑터로 분리해 두었고, 기본값은 `mock` 입니다.

## 2. 시스템 구조

```
 [IP 카메라들] ─RTSP─▶ ┌────────────── backend (Python) ──────────────┐
                       │ stream.py   : RTSP/영상파일 프레임 읽기        │
                       │ detector.py : YOLO (사람·포즈·안전모·화재)     │
                       │ tracker     : 사람별 track_id 유지 (ByteTrack) │
                       │ situation.py: 상황 판단 상태머신 ★             │
                       │ dispatcher.py: 신고 에스컬레이션 (mock/SMS)    │
                       │ main.py     : FastAPI REST + WebSocket          │
                       └───────────────┬───────────────────────────────┘
                                       │ WebSocket (이벤트, 박스 좌표)
                                       ▼
                       ┌────────────── frontend (브라우저) ────────────┐
                       │ 분할 그리드 / 확대 뷰 / 좌우 넘김             │
                       │ 이벤트 패널 / 긴급 모달 / 설정                 │
                       └───────────────────────────────────────────────┘
```

| 구분 | 기술 | 이유 |
|---|---|---|
| 영상 입력 | OpenCV (RTSP, mp4) | 대부분의 IP 카메라가 RTSP 지원 |
| 객체/포즈 인식 | Ultralytics YOLO (`yolo11n-pose`, 안전모/화재 커스텀 모델) | 실시간, 가벼움, 학습 쉬움 |
| 추적 | ByteTrack (Ultralytics 내장) | 사람별 시간 흐름 판단에 필수 |
| 서버 | FastAPI + WebSocket | 비동기, 간단 |
| 화면 | HTML/CSS/JS (빌드 없이 실행) → 필요 시 React 전환 | 2주 일정에 맞춘 선택 |
| 브라우저 영상 | 1차: 서버가 처리한 MJPEG 스트림 / 2차: WebRTC(mediamtx) | 브라우저는 RTSP를 직접 못 재생 |
| 저장 | SQLite (이벤트 로그, 스냅샷 경로) | 설치 불필요 |

## 4. 시연 시나리오 (10/28)
1. 9분할 화면 → 3×2로 변경 → 다시 16분할 (사용자 설정 시연)
2. 카메라 클릭 → 확대 → ← → 로 다른 카메라 넘기기
3. 작업자가 안전모 없이 등장 → 노란 경고
4. 위험구역 진입 → 주황 경고
5. 사람이 쓰러짐 → "쓰러짐 감지" → 10초 무반응 → **긴급 경보 + 119 카운트다운** → 자동 신고(mock) 기록 확인
6. 같은 상황에서 관리자가 `오탐 취소` → 신고 안 됨 확인

## 5. 리스크와 대응
| 리스크 | 대응 |
|---|---|
| 오탐으로 인한 허위 신고 | 시간 기반 상태머신 + 카운트다운 취소 + 기관 직접 연동은 협의 후 |
| 카메라 수 증가 시 GPU 부족 | 카메라별 초당 처리 프레임(예: 5fps) 제한, 작은 모델 사용 |
| 안전모/화재 데이터 부족 | 공개 데이터셋(Hard Hat, D-Fire) 활용, 현장 영상 추가 학습 |
| 개인정보(영상) | 영상 외부 전송 최소화, 신고 시 스냅샷만, 접근 권한 관리 |
